# 검증 범위

## 재현 가능한 검사

| 검사 | 명령 | 확인 내용 |
|---|---|---|
| 규칙 및 그래프 | `python evals/run_evals.py` | 날짜·중복·필수값·재검색·미리보기·리뷰 게이트, fixture 기대 결과 |
| 회귀 및 승인 | `python -m unittest evals.test_restore evals.test_settings -v` | URL 이스케이프, 잘못된 주소, 근거 없는 추출, 0건 안내, 승인 전 SMTP 미호출, 키 설정 CSRF |
| 대시보드 | `node evals/test_dashboard.cjs` | 날짜 구간, 통과율, 빈 상태, 스트림 마지막 줄, HTTP 실패 |

Python 테스트는 외부 발송을 mock으로 대체하거나 DRY_RUN을 사용한다. 키 설정 테스트는 임시 `.env`를 사용한다.
CI는 API 키를 요구하지 않고 검색 fixture로 실행한다. Node는 프론트엔드 검사에만 필요하며 앱 실행에는 필요하지 않다.

## 로컬 검증 기록

- Python 3.12 환경에서 기존 평가 **19/19 PASS**.
- 회귀 및 설정 검사 **9/9 PASS** (실발송 모드 승인 검사는 SMTP mock 사용).
- 프론트엔드 self-check PASS.
- 기준일 `2026-11-02` fixture: 유효 4, 제외 4, 7일 이내 마감 2, 검증 통과율 50%.
- 별도 실제 Tavily/Claude 검색에서 검색 → 추출 → 검증 → 메일 미리보기 → 승인 대기까지 확인.
- 데스크톱 및 390px 화면에서 UI 확인. 검색 후 창 너비를 줄일 때 진행 막대가 넘치는 문제 수정.

## 결과 해석

평가 스크립트의 100점은 소규모 fixture에 대한 7개 규칙 항목의 합계다.
모든 공모전 사이트에 대한 정확도, 검색 재현율, 실제 서비스 운영 지표를 의미하지 않는다.
실검색 결과와 유효 건수는 날짜·검색 응답·발송 이력에 따라 달라진다.
SMTP 실제 전달과 받은편지함 도착은 이 공개 준비 작업에서 검증하지 않았다.
